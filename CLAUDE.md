# Watt Disco – indoor cycling training app

Built with AI, by cyclists for cyclists. A Python app that connects to a smart trainer, a power meter and heart rate straps over Bluetooth, guides structured workouts, records the ride and uploads it to Strava.

## Stack
- Python 3.12, managed with `uv`
- `bleak` for Bluetooth LE (Cycling Power 0x1818, Heart Rate 0x180D, FTMS 0x1826)
- `openant` for optional ANT+ (power, heart rate, FE-C trainer). Needs a USB ANT+ stick and libusb. BLE-only works without it.
- `FastAPI` + `uvicorn` serving a WebSocket and static pages from `src/wattdisco/web/`
- `pywebview` opens the app in its own native window (no browser). `wattdisco` opens the window, `wattdisco serve` is browser-only for development.
- Frontend: plain HTML, CSS, JS (no framework). Canvas or SVG for charts.
- `stravalib` for upload; Strava sign-in uses the shared Watt Disco app through `relay/` (a Cloudflare Worker holding the client secret, never the ride data), or the rider's own keys in `.env`
- `fit-tool` (BSD-3-Clause) to write and, in tests, read back .fit files
- `pytest` for tests

## Layout
```
src/wattdisco/
  ble/      scanner.py, heart_rate.py, power.py, ftms.py
  ant/      stick.py, profiles.py, source.py   (optional ANT+)
  core/     session.py, smoothing.py, workout.py, recorder.py, plans.py, progress.py, ftp_history.py, hrv.py
  export/   fit.py, strava.py, csv_export.py
  sim/      simulator.py   (fake sensors and replay of recorded rides)
  server.py
  web/      one page per screen, shared theme.css, live.js (ships inside the package)
packaging/  PyInstaller spec, launcher, icon, make_dmg.sh (apps built by .github/workflows/release.yml)
design/     concept screens (*.dc.html, optional PNG copies), visual reference only, never served or shipped; kept locally, not in the repository (.gitignore)
tests/
```

## Rules
- Everything must run with `--sim` (simulated sensors). Never require hardware to develop or test.
- Transport code lives only in `ble/` and `ant/`. The rest of the app sees plain Python objects (`PowerSample`, `HrSample`).
- Record all sensors in every ride, even those not chosen as the main source.
- Keep the real-time path light: no blocking I/O in the BLE or WebSocket loops.
- Rides, settings and the Strava sign-in live in the per-user app folder (`config.DATA_DIR`: macOS ~/Library/Application Support/Watt Disco, Windows %LOCALAPPDATA%\\Watt Disco; `WATTDISCO_DATA` overrides), never next to the code, so the app runs from an installed package. Tests always pass their own temporary folder.
- Nothing leaves the rider's computer except what `PRIVACY.md` describes (Strava upload, and the sign-in through the relay). A new network request, stored field or third-party service updates `PRIVACY.md` in the same commit.
- The app's licence is PolyForm Noncommercial 1.0.0: "free, source available", never "open source". New dependencies, fonts and images must be free and allow this (no GPL code in the app).
- Small commits, one feature per commit. Run `pytest` before committing.

## Screens and flow
The app starts in its own window on the launch screen, scans and reconnects devices in the background, then moves on to the connect screen (on the very first start, `setup.html` first asks units, FTP (or lines up the ramp test), weight and max heart rate; settings saved before it existed count as set up). After a ride, TRAIN goes back to that ride's summary until the rider discards it, uploads it, presses "Done · next ride" or starts another ride (`review.json` in the data folder, so a restart keeps it). UI stays HTML/CSS/JS, never a Python GUI toolkit. All Bluetooth goes through Python, never Web Bluetooth.

1. **Launch**: neon logo (disco ball with bolt, "Watt" in script, "DISCO" straight), message "Built with AI, by cyclists for cyclists" (the app was built with AI; it has no AI features, so the line never says the app is AI).
2. **Connect devices**: scan over Bluetooth and ANT+ (shown as a BLE or ANT+ tag per device; show "No ANT+ stick found" when none is plugged in), auto-reconnect last devices, battery level per device (Bluetooth battery service; a warning on the ready screen at 20 % or less), roles per device (power, cadence, control, heart rate), power-meter zero offset, trainer spin-down calibration ("Calibrate" on a connected trainer: FTMS Spin Down Control 0x13, the trainer's Fitness Machine Status says when to stop pedalling and whether it worked, Indoor Bike Data gives the speed; a dialog walks the rider through warm-up, speed band and stop; refused during a ride; a trainer without it is sent to its maker's app; the date is kept per device), CORE body temperature row marked "coming later". A device that is lost, silent, slow to connect or not found says in plain words what to do (wet the strap, pedal to wake the power meter, close other apps holding the trainer). "Copy diagnostics" (footer) shows and copies the app and system versions, the devices by name and the end of the log (`core/diagnostics.py`: `DATA_DIR/logs/wattdisco.log`, rotating, 1 MB × 4; changes only, never sensor values or secrets) for a bug report; nothing is sent.
2b. **Multiple sensors found**: when more than one power source or heart rate sensor is detected, choose the main sensor for each. Offer the sensor comparison.
3. **Workout editor**: phases with colours, duration, power (W and % FTP), cadence target. A plain-words description in watts sits above the chart ("Warm-up 10:00 @ 108–189 W · 5 × 8:00 @ 297 W, 4:00 recovery @ 135 W · …", repeats folded), and the chart shows a watt axis and each phase's power. "Intervals − / +" makes every work phase 5 W harder or easier together; warm-up, recoveries and cool-down stay. Workouts are stored in % FTP; built-ins are read-only (saving makes a copy). "Import" reads .zwo (Zwift), .erg and .mrc files into the rider's own workouts (`core/workout_import.py`): phase types follow each step's power, steps under 10 s join the one before, free ride and max effort parts get a fixed target, and the editor says what was changed.
4. **Ready to ride**: WORKOUTS / CLIMBS / JUST RIDE above the picker. JUST RIDE (built-in `just-ride`, category ride, `Workout.open`, `core/workout.OpenRidePlayer`) is a ride with no workout and no target: the trainer rides like a flat road (gears set the effort), the clock counts up until the rider ends it (at most 6 h), everything is recorded and summarised as usual; the ride screen shows estimated speed and distance where the target would be (nerd: speed, distance, W/kg, time), the chart's axis grows with the ride, and the summary chart has no target blocks; never in the editor or in plans. A home band on top (this week or the plan's week, form, last ride; `/api/home`); the workout picker lists ★ favourites first (kept in settings) with a length filter (all, ≤ 45, 46–75, 75+ min) and a type filter (only the types that have workouts; both remembered per browser); a line under WORKOUTS / CLIMBS / JUST RIDE says what each is; the plan's next session is listed first in the picker; FTP and weight show next to the workout's numbers and change in place (✎); a "This ride" line sums up every ride option, and the option panels fold away under it (Change / Hide options, remembered per browser); ERG or free ride (FTP tests suggest theirs: ramp in ERG, 20 min test in free ride), ERG interval changes as a step or a 3 s ease (with an info button), power source (trainer or power meter), smoothing (RAW, 3 S, 10 S). Smoothing is chosen here only, not on the workout screen. "Start and stops": start NOW (after a 3-2-1 count-in with ticks) or WHEN I PEDAL, and auto-pause ON/OFF (a setting: 5 s without pedalling pauses, pedalling resumes; a pause the rider chose waits for the rider; FTP tests never pause on their own), and Sound ON/OFF. "Ride numbers size" NORMAL, LARGE (1.2×) or EXTRA LARGE (1.4×) for riding further from the screen (per browser). A ride the app never stopped (crash) is offered here: continue it where it was (paused until you pedal) or save it as it is.
5. **Workout (main)**: power is the main number. Workout chart in the middle with colour-coded phases, HR curve drawn like power, zoom control, nerd mode, big numbers and sensor comparison in auto-hiding control docks (each appears only while the pointer is over its place, top or bottom of the chart, or after a tap there on touch screens, and fades shortly after; a thin handle hints where; keys work without showing it; shortcuts Space pause, N nerd, B big, C compare, +/− zoom, F fit; in nerd mode also ↑/↓ interval ±5 W, S skip) so the riding view shows only data. Sound cues (Web Audio tones, no sound files): a tick in each of the last 3 s of a phase, a tone as the next starts, three notes at the end, also on the big and compare screens; muted with the speaker at the end of the top strip (also on ready, big and compare), M, or Sound ON/OFF on the ready screen (a setting, `settings.sound`); silent in a window nobody has clicked or typed in, and in a sped-up simulation. The screen stays awake while a ride runs. The phase badge and the power label carry the zone number (Z1–Z6), so zones never depend on colour alone; chart labels too. Nerd mode explains its numbers the first time (and on the ? button in the top dock). Every new ride opens fitted (the whole workout in the chart); a zoom picked during the ride stays for that ride. The dock is split: view, compare, metrics and zoom over the top of the chart; interval controls, Pause and End ride on the bottom edge of the chart (over the time axis), in neon pink (`.btn--pink`; Pause yellow, End ride filled red). On phones (touch, under 600 px) both sit in the page above and below the chart, always shown; a small window with a mouse keeps them floating and hiding. In nerd mode the bottom dock's interval controls make only the current phase harder or easier in 5 W steps (the chart and the recorded target follow) and skip to the next phase (tap twice). Pause stops everything (workout clock, recording, ERG grip on the trainer) until resume. The pause card shows the ride so far (riding time, average power, load). End ride (dock and pause card, also on Big) is held for about a second while it fills (`dock.holdToConfirm`; from the keyboard, press twice) and sits apart from Pause. Under NEXT, the next three phases show as small blocks in their zone colour with their watts. A warning in words (ERG released, trainer not answering, a silent sensor) also makes the number it is about pulse in yellow. Power on top as the biggest number (in nerd mode with a recent average in a small pill next to its label, in the zone of that average); heart rate below in the middle as the second biggest (in nerd mode with a recent average in a pill under it, in the heart rate colour). Each pill has a dropdown for its window: 30 s (default), 1 min, 5 min or 10 min, remembered per browser. Live traces only under the big numbers: heart rate shows as heartbeat rings (a dot that swells and sends out a fading ring on each beat, at the real heart rate with slight beat-to-beat variation; the number pulses with it; never an ECG or heart monitor look, so nothing reads as a medical reading) and the cadence wave draws one hump per pedal stroke. Main sensors are chosen on the sensors screen (2b), never on the workout screen. "+ Metric" adds tiles for extra values (core temperature, skin temperature, heat strain, W/kg, estimated speed and distance) when a source provides them; the tiles sit in the top row between power and the interval info. ERG / FREE is centred over the target number.
6. **Workout nerd mode**: target shown as a ring whose dot moves round as power goes under or over the target (±5 % band marked), difference to target, on-target %, and the difference between power sources as a second ring (teal, ±2 % band). Cadence is as big as the target number, with a target bar whose line moves as cadence goes under or over the phase's cadence target (also in standard mode).
7. **Big numbers**: power, heart rate, cadence very large.
8. **Ride summary**: three views, Basic, Nerd and Compare (the layout replaces `design/Summary` and `SummaryNerd`). Headline numbers are tiles that show the change against the ride chosen in "Compare with" (default: the last ride of the same workout, else the previous ride; also the 28-day average or any earlier ride; `web/summary-compare.js`). An FTP note sits next to the title: after an FTP test, the new FTP (already set, with undo); after any other ride, a suggestion when 95 % of the best 20 minutes beats the FTP. Basic shows time in effort zones (by actual power), not time in phases, estimated average speed and distance, and the ride's best 5 s, 1 min, 5 min and 20 min (★ when it is the best ever on a real ride). "How did it feel?" (1–10 and a note, saved as they change, `<id>.notes.json`). Right after a ride (while it waits for review) and not rated yet, a card asks for the 1–10 once; Skip, or "Don't ask again" (per browser), which the panel's "Ask me after each ride" line switches back on. A one-sentence headline sits under the title (length or FTP test or time to the top, on-target %, average power against the last ride of the same workout, new bests ★), and a Strava chip next to the date (On Strava as a link, Uploading, Failed, Not on Strava). The nerd view explains its numbers the first time (and on the ? button). A failed Strava upload says why and offers Retry upload. "Save CSV" exports the whole ride, one row per second with every sensor in its own columns.
9. **Ride summary nerd**: a one-screen dashboard. One row of tiles, each with its change and a sparkline over your recent rides: weighted power, intensity, training load, variability, on-target %, HR drift, watts per beat (weighted power ÷ average heart rate), aerobic threshold from DFA α1 (`core/hrv.py`: the heart rate, and power, where α1 of the strap's RR intervals crosses 0.75; with an info button that explains it and plots α1 per window, or says why the ride shows none); the ride chart with a power − target strip under it; left/right balance from a dual-sided power meter (the ride, first and second half, per interval as an L/R column); time in power zones and heart rate zones; deviation from target (share under, within and over ±5 %, mean, mean absolute, standard deviation, max over and under, longest stretch off target); per interval target, average, difference, on-target %; power source difference.
9b. **Ride summary compare**: this ride and the chosen one side by side (every number and its change), both power curves (against the 28-day average: the best of those 28 days), the two rides laid over each other on the workout clock (power and heart rate, 30 s average), and, for the same workout ridden before, interval by interval power and heart rate with the heart rate change.
10. **Upload**: Strava only. Connect once with OAuth, then optional auto-upload. Also save .fit file. Follow Strava's brand guidelines: a plain text "Connect to Strava" button (no Strava image or logo in the repository or the app), links back to an activity read "View on Strava" (`.strava-link`), "Strava" in plain text only (never styled like a logo), never in the app's name or icon, never implying Strava endorses the app.
11. **Sensor comparison** (COMPARE, was the test bench; not in the tab bar except while it is open: reached with C or the dock during a ride and from the summary and upload screens): full screen, power on top and heart rate below (more riders have two power sources). Runs with the ride on its own: starts when the workout starts, skips pauses, ends when the workout ends (no start or stop button). Every source of a kind is shown, up to three (A, B, C; A is the main sensor, tap another to make it A): current value on the left, mean on the right, chart in the middle (Raw, 3 s or 10 s average for the chart and its difference strip only, remembered per browser; the numbers stay raw), then per source against A the live difference, mean difference, lag and correlation. A finished ride's comparison is rebuilt from its recording, so it and its CSV export stay available from the summary and upload screens ("Compare sensors"). In the app window, downloads (CSV, .fit) open a native Save dialog through `app.Files` (pywebview js_api) instead of opening the file in place.
12. **History** (tab HISTORY): every finished ride, newest first, each opening its summary. Grouped by week (each week's rides, time and load), with a ride type filter and a search by name or note. Per ride: date and time, name (tags SIM, FTP TEST), duration, average power (in the zone of that power), weighted power, training load, average heart rate, estimated distance, and "View on Strava" or "Upload". Totals above the list for 7 days, 28 days or all (rides, time, distance, work, training load). Simulated rides are never in the history (nor in Progress): a simulated ride is recorded to `sim-ride/` next to `rides/`, which keeps only the latest one so its summary, .fit, CSV and comparison still open right after it; the folder is emptied when the next simulated ride starts and at app start. The list scrolls inside the card on desktop. Each row has a delete button (deletes at once, with Undo in a toast; the files wait in `deleted/` for 7 days); a FEEL tag (1–10, coloured easy to all out) with the note as its tooltip; Strava shows View on Strava, Uploading… or Failed · retry; a deleted ride that ticked off a plan session leaves that session done. Rides that ticked off a plan session get a PLAN tag.
13. **Training plan** (tab PLAN): multi-week plans built from built-in workouts (`core/plans.py`), in four groups shown as tabs (the last one looked at is remembered per browser): Getting started (First steps 4 weeks, Back after a break 6, Base 8), Raise your FTP (Short on time 4, Threshold 6, FTP Builder 6, Sweet spot 8), Top-end power (Sprint power 4, Punch 4, VO2 max 5), Climbing and long days (Strength 6 (seated low-cadence work at 55–60 rpm), Climbing 6, Long rides 8); listed shortest first; each starts and ends with a ramp test. A workout opened from a plan (a session's Open, or Ride it) has a "‹ Plan" button on the ready screen back to where the rider was. Each plan has a difficulty as written (Easy, Moderate, Hard, Very hard), shown as a tag and as the colour of the card's frame only (zone colours: green, yellow, orange, red); the title and the week bars keep the neutral colours. No calendar: the next session is the first one not ridden or skipped, and it is lined up as the selected workout. A finished ride ticks it off when it is that workout, not simulated, and ridden for 80 % of its time (a test: with a result). Next up offers Ride it, Done outdoors (ridden outside or in another app: counts as done) and Skip; Undo last and End plan. "View plan" (on each plan card, and Breakdown on a running plan) lists every week and session with its description, duration, load and a zone strip of its phases. After a week with 2 skips or key sessions under 85 % on target it suggests repeating the week, never on its own. Progress lives in `DATA_DIR/plan.json`. The ready screen says which plan session is picked (or offers it), the summary says whether the ride counted. Plans only suggest: targets stay the workouts' own % FTP. "Days a week" (2–6) and "Session length" (45–120 min, or as planned) tailor a plan: before it starts they preview every plan and are used when one starts; on a running plan they apply from the current week on. Fewer days drop easy rides first, then the last hard sessions (a lighter week drops hard ones first); more days add easy endurance rides; the FTP test always stays. A length refits each session (`workouts.fit_length`: the number of interval repeats, at most 1.5× as written, steady blocks, then warm-up and cool-down; id `<built-in>--<minutes>m`), never the tests; a lighter week uses the next shorter length and never gets longer, so it stays light.
13b. **Climb** (`core/climb.py`): built-in made-up climbs (category Climbs, read-only, never in the editor). The ready screen has a WORKOUTS / CLIMBS switch above the picker (each list apart, each remembers its last pick, no length filter for climbs; history tags climb rides CLIMB). A climb replaces ERG / free ride with Difficulty (25, 50, 75, 100 % of the uphill gradient). Every ride second the rider's power moves them up the road (`core/speed.Road` with the real gradient and the rider's weight + 8 kg bike); the trainer gets the gradient about 1 s ahead through FTMS indoor bike simulation (0x11), only when it changes by 0.2 % or more and at most once a second; downhills at half (down to −5 %), at most 20 %; a flat road while paused and at the top, where the ride is done. A trainer that can't simulate (Fitness Machine Feature 0x2ACC) is named in plain words. Ridden on the workout screen, same layout in standard and nerd: the profile replaces the workout chart (coloured by gradient on its own neon scale, cool to hot: deep teal downhill, teal 0–3 %, cyan 3–6 %, pink 6–9 %, magenta 9–12 %, white-hot (warm white) 12 %+, never the zone colours; the road ridden glows fully, the road ahead a little dimmer; the rider as a dot in the road's colour with a pulsing ring; zoom shows 1, 2, 4 or 6 km of road ahead, or the whole climb), the phase badge says CLIMB and the gradient, the countdown is the distance to the top, the target box shows the gradient with speed (nerd: a gradient ring and speed), and ERG/FREE and the interval controls are hidden. Ticks record distance, height, gradient, the trainer's gradient and speed; summary and .fit use them (altitude, total ascent). Summary of a climb ride: tiles To the top (moving time, or Not at the top), avg power, W/kg, VAM (metres climbed per hour), avg HR, avg speed on the road, climbed, each with its change against the chosen ride (default: the last attempt); Best times · this climb in place of Best efforts (real rides that reached the top, fastest first, `/api/climbs/<id>/times`, this ride marked, ★ when it is the best, difficulty shown when under 100 %; simulated rides never count); the ride chart shows the road ridden, coloured by gradient, instead of target blocks. The Nerd view shows "Power by gradient" in place of the interval table (`summary._by_grade`, the way up only, by the road's gradient whatever the difficulty): for downhill, 0–3, 3–6, 6–9, 9–12 and 12 %+, with the profile's colour swatch and a bar for the share of time: time, average power (in its zone colour), W/kg, cadence, heart rate and speed. GPX import (`core/climb_import.py`, Import GPX on the CLIMBS side of the ready screen): a track or route with heights becomes one of the rider's own climbs (stored with their workouts, category climb, deletable there with a second tap): distance measured on the earth's surface, heights every 10 m smoothed over 100 m, 100 m segments, gradients kept between −10 % and +20 %, with notes on what changed; only the name, distances and gradients are kept, never the GPS positions. In nerd mode the target box shows four live climb numbers next to the gradient ring (`ClimbPlayer.live`): speed, VAM over the last minute, W/kg and "Top in" (time to the top at the last 30 s of power on the real gradients ahead, its finish time on the climb clock in the tooltip; none while coasting). Ghost: your best earlier attempt up the same climb (fastest real ride to the top, read off the loop when the climb starts, `ClimbPlayer.ghost_state`) rides along as a hollow warm-white BEST dot on the profile, and the line under the distance says how far ahead (teal) or behind (pink) you are, in seconds at the same point of the road; on or off per browser (`wd.ghost`) on the ready screen, the top dock or G. Step 5, later: famous climbs built from open data (OpenStreetMap + Copernicus DEM, ODbL, place names only, never race names).
14. **Progress** (tab PROGRESS): one screen, four panels (five once a climb has been ridden: the bottom row then holds three), real rides only (`core/progress.py`). Every panel here, and the ride summary panels that show more when big (the ride charts, both time in zones, best efforts, intervals, and on Compare the table, the power curve and the power and heart rate overlay), have ⤢ to fill the whole window, and "‹ Back" or Escape to return (`components.zoomButton`). Enlarged summary panels show more: time in zones as a table with each zone's watts, time and share; every best effort from 1 s to 60 min with W/kg and % FTP; the interval table adds time, max power, heart rate, cadence and speed. The compare table becomes a dashboard: the biggest changes in words (coloured good or bad where a metric has a better direction), then a chart of every number's change in % and a card per number, grouped into power, heart rate and ride, each in its number's colour with both rides as bars. The enlarged power curve and overlay show both rides where the pointer is, the curve also a bar per duration of the difference; the enlarged nerd time in zones shows power and heart rate zones as rings. Content shorter than the window sits in the middle, and an enlarged panel's title is larger. Pointing at a summary ride chart shows that second's power (and 10 s average), target, heart rate and speed. Every Progress chart zooms (wheel, pinch, − / +), moves (drag) and resets (double-click, ↺), with a readout of the nearest point; a point on the power curve, FTP history and power sources opens its ride. Fitness, fatigue and form per day from each ride's training load (42- and 7-day exponential averages; form is yesterday's fitness minus fatigue). Power curve: best average power from 1 s to 60 min across all rides, 90 or 28 days, with 5 s, 1 min, 5 min and 20 min as tiles. FTP history: every change with its date and source (ramp test, 20 min test, best 20 min, by hand) in `DATA_DIR/ftp_history.json`, rebuilt once from the rides' FTP when it does not exist yet. Power sources across rides: the main power source minus the second one per ride (% and W, lag), its average, trend per week and a ±2 % band. A range (6 weeks, 3 months, 1 year, all) applies to the time charts. Next to the FTP (here and on the Zones screen): critical power and W′ fitted from the best 3, 5, 10 and 20 min of the last 90 days (work = CP × time + W′), with an info button; no CP when the points don't fit, a "?" when CP is well under the FTP (the efforts were not all-out), and a ramp test suggestion when CP is 8 % or more above the FTP. Best times · climbs (`progress.best_climbs`): one line per climb ridden, most recently ridden first: its best time to the top (★, opens that ride), date, W/kg, VAM, difficulty when under 100 %, rides and how many reached the top; "not at the top yet" until one does.

## Design
- Neon style on every screen except the workout data area, which stays clean.
- Ride summary in colour: each tile and panel has an accent (power tiles in the zone of their own number, heart rate pink, cadence cyan, estimates teal, load yellow, variability purple), best efforts in the zone of their watts, the ride's power line in the zone colour of each moment.
- Neon titles are straight uppercase (Chakra Petch, bold), never italic. Only the "Watt" in the logo uses a script font (Yellowtail).
- Fonts are bundled in `src/wattdisco/web/fonts/` as .woff2 with their licences (Chakra Petch and Martian Mono: OFL 1.1, Yellowtail: Apache 2.0) and loaded with local `@font-face` rules in `theme.css`. Never load fonts from a CDN.
- Touch screens: every button and chip at least 44 px. Zones has a Text size (Normal, Large, Larger) for every screen but the ride screens; a larger size lets a page scroll. TRAIN has a search ("4x8" finds "4 × 8") and links to All workouts (`library.html`: every workout as a card with its zone strip, type, length and search filters, Ride and Edit).
- Every sub-page has its way back in the same place: "‹ where it goes" above the page title (`.back-link`: plan breakdown, sensor comparison, upload, a summary opened from History or Progress, TRAIN opened from a plan).
- All buttons neon: cyan outline for normal, filled pink for the main action, filled red (#FF2D55, `.btn--danger`) for End ride, red outline (`.btn--danger-line`) for throwing something away (Discard), yellow outline (`.btn--warn`) for Pause. A pick-one switch (WORKOUTS / CLIMBS / JUST RIDE) is a framed segmented control with the choice filled (`.segmented`), apart from filters (length in teal, workout type in yellow).
- Neon palette: cyan #3DD9FF, pink #FF3D81, yellow #FFC93C, teal #36E3C4, warm white #FFF6E5, muted #A99BC9, background #070B0A: black, the same as the workout screen, on every page (no coloured glow).
- Clean workout palette: background #070B0A, heart rate #FF6B7A, cadence #5CD6FF, power curve in the chart #00E5FF with a dark outline (not white, so it never looks like a neon block edge).
- Workout colours follow effort, not phase type: the zone of the power as % of FTP. Zone colours: up to 55 % blue #2F7DFF, 56–75 % green #1FFF8A, 76–87 % yellow #FFE224, 88–94 % orange #FF8A12, 95–105 % red #FF2D55, above 105 % (VO2 max) purple #B44DFF. Chart blocks are filled with the zone colour (strongest at the target line) and their edges glow like neon tubes; ramps change colour where they cross a zone. Phase badge and target number use the target's zone. The big power number uses the zone of the rider's current power, independent of the workout.
- Power zones are computed from FTP (`config.py`) and shown on the Zones screen (tab ZONES, was Settings), with heart rate zones from max HR (60/70/80/90 %) or threshold HR (81/89/93/99 %). Each ride stores the HR method and reference it started with. Default rider: FTP 240 W, 75 kg. Built-in workouts are defined in % FTP and scale when FTP changes.
- Phase-change warning (last 10 s of a phase): pulsing warm white #FFF6E5 frame, countdown and pill, so it never matches a zone colour. The pill sits at the bottom of the workout chart, above the time axis, and moves up above the bottom dock while the controls are shown.
- The designs in `design/` are `.dc.html` files (plain HTML with inline styles). Read each file before building a screen and take exact colours, sizes, fonts and spacing from it. Do not copy the markup: it uses fixed pixel sizes. Make the pages responsive. If a PNG with the same name exists, look at it too.
- Every screen fits a full-screen window (1280×800 and up) without scrolling. Phones may scroll.
- The window also works at half a screen, next to another app (down to 520 × 520, `MIN_SIZE` in `app.py`). The phone layout starts at 600 px wide, so from 640 px up the desktop layout stays: the ride screens (ready, workout, big, compare, summary) fit without scrolling. Setup screens and the nerd summary may scroll below 820–860 px wide; editor and zones then use one column.

## Behaviour details
- Warn when a sensor sends no data for 5 s (heart rate dropout indicator). Auto-reconnect.
- Power smoothing is display-only. The recorded data stays raw.
- Units: metric or imperial (mph, miles, lb), chosen at the first start or on the Zones screen (`web/units.js`); stored values, .fit, CSV and Strava stay metric.
- Speed and distance are estimated for a flat road with no wind, from power and rider weight plus an 8 kg bike (`core/speed.py`). They go into the .fit records, because Strava needs a distance stream to chart indoor rides.
- ERG mode sets trainer target power through FTMS. Free ride only shows the target. A climb sends the road's gradient (FTMS simulation), never watts.
- ERG sends a new phase's target at once (a step), so the rider is on target as the interval starts. On the ready screen "Interval changes" can switch to EASE 3 S (big changes eased in over 3 s; an info button explains both; remembered per browser, stored in the ride as `erg_ease`). ERG lets go below 50 rpm (2 s) so the trainer never locks the cranks; back above 60 rpm it always eases in again from the rider's power. The screen says "ERG released · cadence low".
- FTP tests (category FTP tests): ramp test (1 min steps from 50 % FTP, +6 % each; FTP = 75 % of the best minute; the ramp ends on its own when cadence stays under 50 rpm) and 20 min test (openers, then 20 min all out in free ride; FTP = 95 % of the average). A finished test sets the FTP; a simulated one only offers it.
- On target means within ±5 % of target power.

## Known hardware notes
- A KICKR accepts only a few simultaneous Bluetooth connections. Connect the power meter and the strap first if needed.
- Power meters send crank revolution data. Compute cadence from deltas and handle counter rollover.
- ANT+ needs a USB ANT+ stick. Without one the app is BLE-only. A sensor that offers both transports may show up twice, let the user choose one per role.
